# 按人论文偏好 — 识别、存储与持续迭代

本 skill 的检索与推荐**默认面向具体某位同学**（个人粒度，而非「全体同学」泛化）。OpenClaw 必须在会话中锚定**该同学是谁**，读写其**论文选择偏好**，并在每次推荐后**更新偏好**，形成闭环。

---

## 1. 身份锚定（必须先做）

在构造 Query 或调用 `feishu_classmate_research_search_works` 之前，必须确定**目标同学的唯一标识**：

| 来源 | 做法 |
|------|------|
| 飞书私聊 / 单聊上下文 | 将对话中的用户视为目标；使用其 **`open_id`**（或技能链中已解析的 `student_open_id`，与多维表里 User 类型字段一致）。 |
| 群聊 @ 某人 | 以被 @ 的成员为检索服务对象；若无 @ 且用户未说明「帮谁找」，**先简短确认**「本次论文列表是给哪位同学用的？」再落笔。 |
| 用户明确说名字 | 若仅有姓名、无 `open_id`，通过 `feishu_classmate_search_users` 或既有成员表解析到 **`open_id`**；解析失败则再次请用户提供可关联账号的信息。 |

**禁止**在已知要为某位同学服务时，仍用匿名或「通用研究生」画像替代其个人偏好。

---

## 2. 偏好应记录什么（选择行为 → 可检索信号）

从该同学对**已提供论文**的实际反应中归纳（证据优先，避免臆测）：

- **正向**：明确说「这篇好 / 有用 / 已读 / 已保存」、要求展开某类方法、反复追问某 venue 或某作者线。
- **负向**：「太老 / 太数学 / 不相关 / 不要 survey」、忽略某批推荐、点名不喜欢的子领域或会议档次。
- **结构化信号**（若与 `manage-papers` 联动）：该同学把某篇记入 Papers、或 `read_status` 变化，可作为**强正向**。

每条偏好更新应能回答：**谁（open_id）**、**在什么主题任务下**、**对哪类论文偏好/排斥**（尽量可写成 Query 修饰词或排序权重说明）。

---

## 3. 存储位置（优先级）

1. **首选 — Agent workspace 记忆文件（不依赖改表）**  
   路径（相对当前 Agent 的 workspace 根目录，与 OpenClaw 其它 `memory/` 用法一致）：

   `memory/paper-preferences/<open_id>.md`

   每位同学**一个文件**；`open_id` 取飞书 User 的 `open_id`（如 `ou_xxx`），文件名做安全字符处理（与现有 `memory/*.md` 命名习惯一致即可）。

2. **可选 — 飞书多维表**  
   若 `feishu_classmate_data_layout()` 中将来出现**专用表**（例如 `paper_search_preferences`），则**以表为准**，文件作迁移或双写策略由团队约定；在表不存在前，**不得**因没有表而跳过偏好读写。

---

## 4. 单文件推荐结构（`memory/paper-preferences/<open_id>.md`）

便于人读、也便于模型续写；建议固定小节：

- **`## 元数据`**：`open_id`、显示名（若有）、`last_updated`（ISO 日期）。
- **`## 稳定偏好摘要`**（3–10 条短句）：偏好的 venue/方向、语言、综述 vs 原创、时效（例如偏好近 3 年）、方法论或应用侧重。
- **`## 近期反馈日志`**：按时间倒序；每条一行或一小段：**日期**、**任务主题**、**用户原话或行为**、**提炼后的检索规则**（例如「加大 CVPR/ICLR，减少纯理论」）。
- **`## 曾明确表态的论文标识`**（可选）：`arxiv_id` / DOI / 标题片段 + **喜欢 / 无感 / 排斥**，供后续「相似/不相似」排序参考。

写入时使用 `apply_patch` 或等效方式**追加或更新摘要**，避免整文件无意义重写；`last_updated` 每次有实质偏好变化时更新。

---

## 5. 检索流程中如何使用偏好

- **Query 阶段**（见 `intent-and-queries.md`）：将摘要中的 venue、时间窗、方法论偏好**融入**多组 Query；将排斥项作为**否定语境**或过滤说明（仍遵守学术源与反幻觉规则）。
- **排序阶段**（见 `evaluation-output-rules.md`）：在同等相关性下，**提高**符合该同学历史偏好的论文；**降低**与其明确排斥信号一致的论文。
- **输出**：可在列表前用一两句话说明「已按某某同学过往偏好调整排序/侧重」，便于可解释性（不泄露他人偏好）。

若文件不存在：视为**冷启动** — 正常检索，并在首轮推荐后邀请简短反馈以建立文件。

---

## 6. 交付后私聊征询（推荐做法）

每次**结构化交付论文列表之后**，在业务流程与机器人权限允许时，**主动向该目标同学发起飞书私聊**（使用其已锚定的 `open_id` 所对应的单聊能力；具体工具以当前部署中的 Lark / OpenClaw 消息接口为准）：

- **消息要点**：一两句复述本轮任务主题；列出与公开展示**一致的编号**（如 1–N）；请对方指出**哪几篇更符合需求**；若有**明显不贴**的篇目，也可请其用编号说明原因（一两句即可）。
- **与群聊的关系**：若列表已在**群聊**中发出，私聊作为**跟进取偏好的主渠道**，避免在群里长篇追问个人口味；若本来就是**私聊**，可在同一轮对话末尾直接追问，无需重复开话题。
- **落盘**：将私聊中的选择与原话整理后写入 `memory/paper-preferences/<open_id>.md` 的「近期反馈日志」，并视情况更新「稳定偏好摘要」「曾明确表态的论文标识」。

若当前环境**无法**向用户发起私聊（未开通机器人 DM、无可用 `open_id` 发信接口等），则在当前可见渠道用同样问题征询，并在偏好日志中注明「征询渠道受限」。

---

## 7. 持续迭代闭环（每次任务末尾）

在交付本轮论文列表后，**优先完成对该同学的私聊征询（见上一节）**，再在收到反馈后：

1. 根据用户对新列表的反应（含私聊答复），更新 `memory/paper-preferences/<open_id>.md`（日志 + 必要时改摘要）。
2. 若用户通过 `manage-papers` 保存了某篇，可在偏好中记一条强正向（venue/主题线）。
3. 若本轮无任何新信号，可不写文件，但**不要删除**已有历史。

这样，**下一次**同一 `open_id` 的论文搜索应**先 `read_file` 该路径**，再进入 SKILL 主流程的步骤 2 及以后。

---

## 8. 隐私与范围

- 偏好文件**仅按人分文件**；不在 A 同学的文件中写入 B 同学的行为。
- 群内展示时避免朗读完整偏好文件；只使用与当前任务相关的检索调整说明。
- 私聊征询内容仅用于更新**该同学本人**的偏好文件，不在群内复述其详细负面评价（除非对方同意）。
