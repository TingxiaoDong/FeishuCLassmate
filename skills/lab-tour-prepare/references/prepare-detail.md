# 准备期 · 详细步骤

## 输入收集

从用户消息中提取:

- 访客单位/称谓(必填语义)
- 来访日期(默认今天)
- 是否强调某些展区或忌口话题
- 访客国别与语言偏好（用于双语导览）

若识别为外国来宾，必须确认“访客国家语言”（例如日语、韩语、德语等）；若缺失则先追问。

## 个性化路线生成

### 访客画像维度
- 访客类型:产业合作 / 投资考察 / 学术交流 / 招聘与人才合作
- 关注方向:人形机器人、仿真平台、交互体验、工程落地、成果转化
- 沟通偏好:看演示优先 / 听研究逻辑优先 / 看落地案例优先

### 路线打分与排序
1. 为每个可参观展区计算匹配分(0~100):
   - 主题匹配(50%)
   - 合作潜力(30%)
   - 现场可演示性(20%)
2. 将分数最高的2~3个展区前置到导览前半段。
3. 保持安全锚点:
   - 第一站固定「入口开场」
   - 最后一站固定「入口收尾问答」
4. 若用户明确指定必须参观点位,该点位优先级最高。

### 输出约束(非常关键)
- 输出 Doc 时,二级标题顺序就是执行路线顺序。
- 每个章节保留 `【动作：导航到 XXX】` 指令,确保执行期可直接导航。
- 若某低匹配章节被弱化,可写「本节跳过」由执行期自动跳过。
- 外国来宾场景必须输出双语内容：每个章节按“中文段 + 访客国家语言段”顺序组织。

## 读母版

- `plugin_docs.tourTemplate` 可为 Doc token、文档 URL 或由 wiki 搜索得到的定位符。
- 母版中建议使用占位符:`{{访客单位}}`、`{{日期}}`、`{{实验室名称}}`,便于替换。

## 生成正文约束

- **保密**:不得写入保密项目;公开内容仅来自母版、`plugin_docs.publicProjects` 对应 Doc、以及 `labInfo`(配置)。
- **章节**:必须包含 [doc-format.md](./doc-format.md) 所列核心二级标题,可根据个性化路线调整中间章节顺序,便于 `lab-tour-run` 分段播报。
- **唤醒句**:在文档末尾固定一节「唤醒」,写一句口语化口令,例如:「飞书同学,XX 单位的老师到了。」供 Temi / 飞书触发执行期 skill。
- **存储目录**:生成的当次导览 Doc 必须存储在【知识库-公共协作区-导览母版】目录下，不放到根目录或其他目录。

## 交付物

- 新建 Doc 的 **document_id** 与 **URL**(发给教师归档)。
- 可选:在同一机器人会话置顶摘要「访客 + doc 链接」,便于现场人手忙脚乱时复制。
- 若为双语稿,在回执中注明使用语言组合（如“中文+日语”）。
