# 项目进度管理Skill

## 前置：获取数据布局
```
feishu_classmate_data_layout()
  → { app_token, tables: { projects, gantt, high_priority_projects }, docs: { lab_knowledge_base, public_projects } }
```
所有项目文档、表格默认写入`docs.lab_knowledge_base`（飞书【Lab知识库】公共协作区），项目列表统一维护在`docs.public_projects`（【公开项目】文档）。

---

## 阶段1：项目信息收集与创建

### 场景A：上传文档创建项目
1. 用户上传项目相关文档 → 调用`feishu_fetch_doc`解析文档内容
2. 自动提取项目核心信息：名称、负责人、起止时间、任务节点、预期产出
3. 将整理后的结构化信息发送给管理员/导师确认，支持修改调整
4. 确认无误后：
   - 在【Lab知识库】-公共协作区-公开项目下创建项目专属文档：`{项目名}`，包含：
     - 项目状态
     - 项目简介
     - 当前目标
     - 当前进展
     - 待完善内容
     - 后续计划
   - 新增项目到【公开项目】文档，包含以下信息：项目状态和简介，便于索引即可
   - 在`gantt`多维表格新增对应项目，生成初始甘特图节点
   - 自动判断项目优先级：计算任务密度（总任务数/总天数）和截止时间紧急度，标记是否为「任务繁重且时间紧急」项目
   - 若标记为「任务繁重且时间紧急」项目，后续自动执行以下操作：
     1. 项目优先级字段更新为「高优先级（任务重时间紧）」
     2. 自动在`high_priority_projects`多维表新增记录，创建专用高颗粒度跟踪表
     3. 触发高优先级项目专属跟踪逻辑（按阶段2高优先级项目特殊规则执行颗粒度分级检查和提醒）
     4. 发送即时通知给项目负责人和导师，告知项目已标记为高优先级并启动专项跟踪

### 场景B：自然语言创建项目
1. 用户说"我要新建项目/记录项目进度" → 判断是否为新项目
2. 是新项目则通过`feishu_ask_user_question`收集核心信息：项目名、负责人、起止时间、主要任务节点
3. 整理信息后发送给用户确认修改
4. 确认后同场景A步骤4创建项目资源：
   - 先创建项目专属文档
   - 再添加项目索引到【公开项目】文档
   - 最后写入甘特图

## 阶段2：进度协作甘特图管理（每日12:00 cron自动触发）

### 通用检查逻辑（所有项目）
1. 遍历`gantt`表所有进行中项目，每个项目只检查**最近的2个待完成任务节点**
2. 节点时间已过但状态为未完成：节点标红，记录逾期
3. 单个项目累计≥2个逾期节点：
   - 调用`feishu_send_message`私信项目负责人：
     > 【项目进度提醒】你负责的《{项目名}》目前有{逾期数}个任务节点已逾期哦(｡ŏ﹏ŏ)
     > 逾期节点：{节点1名称}（逾期{X}天）、{节点2名称}（逾期{Y}天）
     > 请问目前是遇到什么卡点了吗？我可以帮你拆分任务、协调资源或者调整时间安排(`・﹏・´)

### 高优先级项目特殊逻辑（任务繁重且时间紧急的项目）
1. 识别到高优先级项目后，自动在`high_priority_projects`多维表新增记录，创建专用高颗粒度跟踪表
2. 跟踪节点颗粒度自动分级：
   | 颗粒度 | 检查频率 | 提醒规则 |
   |--------|----------|----------|
   | 3天级 | 每3天检查 | 节点过半仍无修改记录 → 发提醒 |
   | 1天级 | 每日检查 | 节点过半仍无修改记录 → 发提醒 |
   | 2小时级 | 每2小时检查 | 节点时间到了无修改记录 → 立即发提醒 |
3. 自动判断进度合理性：对比历史更新频率、任务量预估完成度，异常时自动调整颗粒度
4. 所有高优先级项目的进度表同步存储在【Lab知识库】公共协作区中

## 阶段3：智能协助与帮扶
所有提醒消息均为帮扶导向，禁止催促语气，提供以下支持选项：
1. **卡点排查**：用户反馈有问题时，询问具体卡点，查询知识库相关解决方案给出建议
2. **任务拆分**：针对逾期或困难的大任务，自动拆分为多个可快速完成的小任务，降低启动成本
3. **时间调整**：用户提出时间不够时，协助重新规划甘特图节点，同步更新飞书表格
4. **资源协调**：需要其他成员支持时，自动查询相关技能的同学，提供协调建议
5. **拖延干预**：识别到启动困难/拖延情况时，先做小目标引导，帮助用户快速推进第一步

---

## 阶段4：汇总汇报（每周日18:00 cron自动触发）
1. 统计本周所有项目进度、逾期情况、风险点
2. 生成汇总报告，写入【Lab知识库】公共协作区：`{YYYY-MM-DD}-项目进度周报`
3. 调用`feishu_send_message`将报告发送给导师/管理员，包含：
   - 整体项目进度概览
   - 逾期项目列表及风险等级
   - 高优先级项目进展
   - 需要协调的问题建议

---

## 字段约束
| 字段 | 有效值 |
|---|---|
| 项目优先级 | `普通`、`高优先级（任务重时间紧）` |
| 节点状态 | `未开始`、`进行中`、`已完成`、`逾期` |
| 颗粒度 | `3天`、`1天`、`2小时` |

---

## 失败降级
- 【Lab知识库】公共协作区ID不存在 → 回复"请先配置飞书【Lab知识库】公共协作区ID"，停止操作
- 甘特表查询失败 → 跳过对应项目，记录错误日志
- 消息发送失败（用户未加机器人） → 记录到项目日志，下次检查重试
