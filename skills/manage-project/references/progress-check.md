# 进度检查指南

## 执行时间
每日12:00 cron自动触发

## 通用检查规则（所有项目）
1. 遍历`gantt`表所有进行中项目，每个项目只检查最近的2个待完成任务节点
2. 节点时间已过但状态为未完成：
   - 节点标红
   - 记录逾期天数
3. 单个项目累计≥2个逾期节点：
   - 调用`feishu_send_message`私信项目负责人：
     > 【项目进度提醒】你负责的《{项目名}》目前有{逾期数}个任务节点已逾期哦(｡ŏ﹏ŏ)
     > 逾期节点：{节点1名称}（逾期{X}天）、{节点2名称}（逾期{Y}天）
     > 请问目前是遇到什么卡点了吗？我可以帮你拆分任务、协调资源或者调整时间安排(`・﹏・´)

## 高优先级项目特殊逻辑
1. 跟踪节点颗粒度自动分级：
   | 颗粒度 | 检查频率 | 提醒规则 |
   |--------|----------|----------|
   | 3天级 | 每3天检查 | 节点过半仍无修改记录 → 发提醒 |
   | 1天级 | 每日检查 | 节点过半仍无修改记录 → 发提醒 |
   | 2小时级 | 每2小时检查 | 节点时间到了无修改记录 → 立即发提醒 |
2. 自动判断进度合理性：对比历史更新频率、任务量预估完成度，异常时自动调整颗粒度
3. 所有高优先级项目的进度表同步存储在【Lab知识库】公共协作区中
